# Pet Comic 技术设计

## 1. 技术目标

本文档把 [项目设计](./项目设计.md) 转换为可以直接开工的代码边界。第一版优先保证本机可运行、任务可恢复、模型调用可替换、产物可追踪和单格失败可重试。

运行形态固定为两个独立进程：FastAPI 后端和 Next.js 前端。后端启动时自动创建运行目录、SQLite 文件、表和必要的子目录。

## 2. 技术栈

| 层 | 技术 | 约束 |
|---|---|---|
| 后端运行时 | Python 3.12+、FastAPI、Uvicorn | Python 代码放在 `backend/` |
| 依赖管理 | `pyproject.toml`、uv | 使用 uv 创建环境和锁定依赖 |
| 工作流 | LangGraph | Graph state 不保存图片二进制和 SDK 对象 |
| 文本/视觉 | LangChain + OpenAI-compatible Responses API | 协议固定为 Responses API |
| 图片生成 | 官方 OpenAI Python SDK + 项目 Image Provider Adapter | 使用 `images.edit` 或 `images.generate` |
| 数据库 | SQLite + SQLAlchemy 2 + Alembic | 应用库与 checkpoint 库分离 |
| 配置 | Pydantic Settings + `.env` source | 代码默认值 < `.env` |
| 图片处理 | Pillow，必要时 SVG/Pillow 绘制文字图层 | 生成图默认无字 |
| 前端 | Next.js App Router、React、TypeScript | 独立进程运行 |
| 前端样式 | Tailwind CSS、shadcn/ui | 组件保持可替换 |
| 前端数据 | TanStack Query、原生 `EventSource` | REST 快照 + SSE 新事件 |

Responses API 支持通过 `input_image` 传入图片 URL、data URL 或文件 ID；本项目对外部输入先落盘，视觉适配层按 LangChain 的图片消息格式读取受控本地资产。[OpenAI Developer quickstart](https://platform.openai.com/docs/quickstart/make-your-first-api-request)

## 4. 配置

### 4.1 配置来源

运行参数由 `pydantic-settings` 的类型化设置模型读取。加载顺序为：代码默认值 → `.env`；未配置字段回退到代码默认值。数据目录默认是当前用户目录下的 `.pet-comic`，也可以通过 `PET_COMIC_DATA_DIR` 覆盖。供应商和模型绑定不属于 `.env`，全部由 `.pet-comic/app.db` 和设置页面管理。

服务启动时读取一次 `.env`。修改文件后重启 FastAPI 生效。提示词不走 settings，在每个 LangGraph 节点开始时从 `backend/prompts/` 读取。

### 4.2 默认配置

仓库提供 [backend/.env.example](../backend/.env.example)，包括数据目录、图片限制、并发、请求超时、SSE 心跳、图片尺寸、质量和日志级别。

`.env` 不提交到仓库；供应商 API key 只存在 SQLite，不进入配置文件、任务目录或日志。

### 5.2 `用户目录/.pet-comic/langgraph.db`

该数据库只由 LangGraph checkpointer 使用，保存 graph checkpoint、线程状态和恢复所需的 LangGraph 内部数据。应用代码通过 LangGraph checkpointer API 访问，不直接查询其内部表。

`thread_id` 使用 `task_id`。执行批次用应用层 `execution_id` 和 checkpoint namespace 区分；每次重跑建立新的 `execution_id`，原执行只读保留。

## 7. 领域模型与状态

### 7.1 宠物档案

```python
class PetProfileStatus(str, Enum):
    DRAFT = "draft"
    READY = "ready"
    DISABLED = "disabled"
```

`PetProfile` 由后端生成稳定的 UUID/ULID `pet_id`。建档输入支持 1–3 张证件照；档案提取失败时不创建可用档案，页面保留当前输入并显示错误。档案提取和角色卡生成是两个可独立重试的节点，成功项记录后跳过。

只有 `ready` 档案的结构化外观和摘要会进入图片理解上下文。删除使用软删除，历史任务继续保留对角色卡和图片的引用。

### 7.2 LangGraph state

Graph state 使用 `TypedDict` 或等价的类型化结构，字段只保存 JSON 可序列化的业务数据和文件引用：

```text
task_id
execution_id
input_asset_ids
pet_contexts
understanding_records
scene_candidates
comic_script
panel_specs
panel_results
task_warnings
cancel_requested
```

state 不保存图片 bytes、base64、LangChain message、OpenAI SDK response 或数据库 session。并行节点使用按 `item_id` 合并的 reducer，避免 fan-out 结果互相覆盖；数据库 `task_items` 是恢复和幂等判断的权威索引。

## 8. LangGraph 工作流

### 8.1 宠物建档图

```text
validate_pet_input
  → extract_pet_appearance
  → generate_character_card
  → finalize_pet_profile
```

`extract_pet_appearance` 一次将 1–3 张证件照提交给视觉模型，输出结构化外观和摘要。`generate_character_card` 使用证件照调用 `images.edit`，要求单只宠物、透明背景、尽量完整身体。角色卡成功后档案状态才变为 `ready`；失败保持 `draft`。

### 8.2 漫画任务图

```text
validate_input
  → normalize_assets
  → snapshot_pet_context
  → understand_images (fan-out)
  → aggregate_understanding
  → select_scenes_and_write_script
  → validate_script
  → expand_panel_specs
  → generate_panels (fan-out)
  → render_text_layers
  → compose_grid
  → finalize
```

每个执行批次开始时读取当前 `ready` 宠物档案，展开为本批次固定的文本上下文。档案在执行期间被停用或删除，不影响已经展开的批次；下一次继续或重跑重新读取当前状态。

`understand_images` 为每张图片返回结构化图片理解和 `pet_matches[]`。每个匹配包含 `pet_id|null`、区域描述、置信度和理由；程序只接受当前 `ready` 档案中的 ID。

场景选择和剧本写作在领域上分开保存，第一版由一个结构化调用生成。剧本严格包含 9 格，每格包含 `scene_id`、`pet_ids`、动作、情绪、画面提示、对白/旁白和文字布局意图。

`expand_panel_specs` 根据剧本决定参考图：有 `pet_id` 时传对应角色卡，多宠物传多张角色卡；没有 `pet_id` 时使用该场景引用的原始图片。`draft/disabled` 档案不进入上下文，也不能提供角色卡参考图。

## 9. 模型适配层

### 9.1 LangChain Responses 适配器

`LangChainResponsesProvider` 负责创建 OpenAI-compatible LangChain chat model、读取 Prompt Registry 模板、传入文本和图片消息、请求结构化输出、将响应解析为 Pydantic 领域模型，并返回规范化 usage、模型、耗时和错误码。

视觉理解和文本生成均通过此适配器调用 Responses API。供应商或模型不支持 Responses API、图片输入或结构化输出时直接返回明确错误，不自动退回 Chat Completions。

### 9.2 Image Provider Adapter

`ImageProviderAdapter` 不经过 LangChain，只依赖官方 OpenAI Python SDK 的 Images API。宠物角色卡和有参考图的漫画格统一调用 `images.edit`；漫画格如果没有角色卡，则使用剧本场景引用的原始图片调用 `images.edit`；角色卡和场景原图都缺失时，在调用前返回错误，不发起生图请求。响应图片先保存为临时文件，校验后交给 ArtifactStore。

### 9.3 模型目录

Provider Adapter 调用每个启用供应商的 `/v1/models`。模型目录只存在当前 FastAPI 进程内，启动时加载，设置页支持手动刷新；不持久化远端目录，不自动探测模型能力。vision/script/image 绑定保存到 SQLite，绑定保存时和任务提交时校验供应商及模型 ID。

## 10. Prompt Registry

```text
backend/prompts/
├─ pet-appearance.md
├─ pet-appearance.yaml
├─ character-card.md
├─ character-card.yaml
├─ image-understanding.md
├─ image-understanding.yaml
├─ comic-script.md
├─ comic-script.yaml
├─ panel-image.md
└─ panel-image.yaml
```

Markdown 保存正文，YAML 保存 `prompt_id`、用途、变量名和说明。每个 LangGraph 节点开始时读取当前文件，计算内容 hash 并记录版本；同一节点内所有 item 使用同一版本，节点之间可以使用不同版本。模板变量在模型调用前校验，缺失变量直接报配置错误，多余变量记录警告。

## 11. 任务队列、并发和恢复

FastAPI 进程内维护 `asyncio.Queue`。`max_running_tasks` 默认 1，控制同时执行的任务数；一个任务内部的模型请求由任务级 semaphore 控制，`max_model_requests_per_task` 默认 3。两个参数都在 `.env` 中配置，新执行批次开始时读取并固定。

应用重启时，`running` 标记为 `interrupted`，`queued` 保留且不自动执行，`cancelled` 可由用户点击继续；用户继续后从 checkpoint 恢复。已保存的成功 item 复用，状态不确定的模型请求视为未完成并重新执行。

取消任务写入 `cancel_requested=true`。节点在每个 item 开始前检查；已发出的请求允许完成或超时，成功结果仍然保存，任务最终状态为 `cancelled`。

## 12. API 设计

FastAPI 全部使用 `/api` 前缀；Next.js 开发服务器通过 rewrites 代理到后端。

### 12.1 宠物 API

```text
GET    /api/pets
POST   /api/pets                         # multipart，证件照 1–3 张 + JSON 字段
GET    /api/pets/{pet_id}
PATCH  /api/pets/{pet_id}                # 名字、性格、启用/停用
POST   /api/pets/{pet_id}/retry
POST   /api/pets/{pet_id}/character-card/retry
POST   /api/pets/{pet_id}/trash
DELETE /api/pets/{pet_id}
```

### 12.2 Provider API

```text
GET    /api/providers
POST   /api/providers
PATCH  /api/providers/{provider_id}
POST   /api/providers/{provider_id}/refresh-models
GET    /api/providers/{provider_id}/models
GET    /api/model-bindings
PUT    /api/model-bindings
```

API 返回供应商时只返回脱敏 key 状态，不返回 key 内容。

### 12.3 任务 API

```text
POST   /api/tasks                       # multipart：images[] + params JSON
GET    /api/tasks
GET    /api/tasks/{task_id}
GET    /api/tasks/{task_id}/events      # 只推送连接建立后的新事件
GET    /api/tasks/{task_id}/files/{path}
POST   /api/tasks/{task_id}/cancel
POST   /api/tasks/{task_id}/resume
POST   /api/tasks/{task_id}/retry-failed
POST   /api/tasks/{task_id}/rerun-panel/{panel_index}
POST   /api/tasks/{task_id}/rerun-compose
POST   /api/tasks/{task_id}/trash
POST   /api/tasks/{task_id}/restore
DELETE /api/tasks/{task_id}
```

任务创建支持拖拽/文件上传和高级 HTTP(S) URL；不支持 base64。后端下载 URL 时限制协议、超时、响应大小、Content-Type，并拒绝回环、内网和本机地址。

所有错误统一为：

```json
{
  "code": "MODEL_CAPABILITY_UNSUPPORTED",
  "message": "当前模型不支持 Responses API 的结构化输出",
  "details": {},
  "retryable": false
}
```

`details` 不包含 API key；前端根据 `code` 显示中文提示。

## 13. 事件和 SSE

事件先追加写入 `task_events` 和任务目录的 `events.jsonl`，事务提交后再通知进程内订阅器。事件至少包含 `event_id`、任务/执行/节点/item 标识、类型、时间、状态、进度摘要和错误码；完整剧本、理解记录和图片通过 REST 获取。

任务详情页打开时先请求 `GET /api/tasks/{task_id}` 获取当前快照，再建立 SSE。SSE 只推送连接建立后的新事件，不回放历史事件；页面断线重连后重新获取任务快照。

## 14. 前端页面

- 宠物列表/详情/新增：上传 1–3 张证件照、填写名字和性格，显示 `draft/ready/disabled`、外观和角色卡缩略图；失败时保留当前页面输入，刷新或关闭后不恢复。
- 任务列表：按状态、日期和是否有最终九宫格筛选，默认按创建时间倒序。
- 创建任务：拖拽/文件选择为主，URL 作为高级输入，显示图片数量和大小校验。
- 任务详情：顶部状态和操作，中间显示九宫格，下方用标签页展示剧本、图片理解、宠物匹配和调用信息；单格只提供查看和直接重试。
- Provider 设置：新增/编辑/启用/停用供应商、隐藏 key、刷新模型、绑定 vision/script/image 模型。
- 运行参数页：只展示当前有效值和来源；修改 `.env` 后重启后端。

前端使用 `apiClient` 统一封装 REST 请求，TanStack Query 缓存快照，原生 `EventSource` 处理任务事件。图片通过文件下载接口获取，不把 base64 放入 JSON。

## 15. 手动验证边界

第一版不建立自动化测试套件，也不提供单独 smoke 命令。开发验证以两个进程启动、配置页连接测试、单宠物建档、3–6 张图片端到端任务、取消/继续、失败 item 重试和单格重试为主。模型调用必须使用真实供应商配置进行人工验证。

## 16. 启动方式

后端启动时自动完成初始化：创建当前用户目录下的 `.pet-comic/`、`pets/`、`tasks/`、SQLite 文件、表和 LangGraph checkpoint 存储。

```powershell
uv run uvicorn app.main:app --app-dir backend --reload
cd frontend
npm run dev
```

前端默认通过 rewrites 访问后端 `/api`；生产部署仍保持两个独立进程。
